CampusDine
Software Requirements Specification

Nonfunctional Requirements

Nonfunctional requirements describe the quality, performance, security, and operational characteristics that the CampusDine system should maintain.


01  Performance: The system should provide a fast response to normal user actions such as browsing menus, checking availability, and viewing orders.

02  Real-Time Updates: Stock and order information should be updated through the real-time layer so that users and canteen staff can receive current information.

03  Security: The system should protect user, order, and payment information using JWT-based authentication and university email verification.

04  Usability: The ordering process should be simple and easy to understand for students, faculty members, canteen staff, and administrators.

05  Reliability: The system should maintain correct order and payment status and should avoid losing confirmed order information during normal operation.

06  Data Integrity: Menu, stock, order, and payment records should remain consistent and accurately linked.

07  Maintainability: The system should be organized using the selected frontend, backend, database, real-time, and authentication technologies so that it can be maintained and updated easily.

08  Availability: The system should be available during normal university and canteen operating hours so that users and staff can access the required services.

09  Scalability: The system should be able to support an increasing number of students, faculty members, orders, and menu items without major performance problems.

10  Compatibility: The system should work properly on commonly used modern web browsers and different screen sizes.
